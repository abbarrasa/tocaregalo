## Users and actors

- USER: manages owned groups, their users and events, and initiates their event draws.
- SUPER ADMIN: may perform all specified management operations and exclusively request explicit draw deletion, but cannot view other users' assignments.
- Group member: a user belonging to a group and participating in its draw; may also own groups.
- Email delivery system: delivers assignment/recovery emails under the specified retry and stale-message rules; configured externally per environment, with local capture in development. Real-provider connection and sender values are deployment inputs.

## User stories

- US-1: As an owner, I want to manage groups and their participants so I can organize gift events.
- US-2: As an owner, I want to manage events and run their draws so each participant is assigned someone to give a gift to.
- US-3: As a participant, I want email notification and a temporary dashboard reveal so I can learn my recipient.
- US-4: As a SUPER ADMIN, I want to delete a draw so an unfinished event can be drawn again or a finished event's draw can be removed without reopening the event.

## Definitions

- Owner: the single user whose ownership authorizes management of a group and its events. The creator is automatically its owner and a participating member. Supporting additional owners is a possible future feature, not current behavior.
- Assignment: a giver, an event, and that giver's recipient.
- Valid draw: with at least three members, each member gives to exactly one other member and receives from exactly one other member of the same group, without self-assignment.
- Invalid assignment: a retained previous assignment marked invalid when insufficient membership prevents replacement; it is not revealable or usable as a current valid assignment. The card displays “Participantes insuficientes”.
- Closed draw: a valid draw that cannot be manually modified or repeated until a SUPER ADMIN deletes it. Automatic replacements under FR-25, including membership additions and recovery from insufficient membership, are explicit exceptions, limited to unfinished events with at least three members.
- Finished event: an event closed manually or automatically, which cannot reopen. A single optional completion field supports both paths; a future value alone does not mean closed. Scheduled closure occurs at the end of the selected day in system time; manual closure writes the current date/time into the same field. Draw blocking applies immediately at the closure boundary, with up to one minute for background closure processing.

## Acceptance criteria

The following criteria apply to permitted actions and valid inputs unless they explicitly test rejection. Open questions constrain their final test cases; they are not implicit decisions.

- AC-1 (FR-1): Creating two groups with the same nonempty name succeeds; creation without a name fails; omitting the description succeeds. Each created group has exactly one owner, its creator, and includes that creator as a participating member; the database enforces a single owner per group.
- AC-2 (FR-2): USER can list and change owned groups but cannot list or change unowned groups through these management operations. Confirmed deletion removes the group, its events, and its draws, retaining member accounts; cancelling confirmation leaves them unchanged.
- AC-3 (FR-3): Missing required fields and duplicate email/phone fail; omitting surnames succeeds. Surrounding whitespace is trimmed from names/email; Symfony rejects invalid emails and case variants of an existing email fail uniqueness. Phones require a `+` country prefix; `00`-only prefixes fail. Backend cleanup strips whitespace/signs except the prefix `+`; formatting variants of the same cleaned phone fail uniqueness. Frontend entry prevents unwanted characters through the specified Vue plugin mechanism.
- AC-4 (FR-4): Passwords shorter than six characters fail. Passwords of six or more characters using letters, digits, symbols, or combinations meet the composition policy without requiring multiple categories. An owner sets a newly created user's initial password; the stored value is a Symfony-generated hash, not the raw password, and Symfony's hasher verifies the correct password and rejects an incorrect one.
  Verify the 4096-byte upper boundary with ASCII and multibyte UTF-8 inputs: valid inputs at 4096 bytes can be hashed and verified; inputs above 4096 bytes fail without account creation or password mutation. Preserve whitespace exactly; the minimum counts characters and the maximum counts bytes.
- AC-5 (FR-5): An owner can create and list users in an owned group, but attempts to modify another member's user data fail and leave it unchanged. An owner cannot delete another account solely through group ownership. SUPER ADMIN permissions follow FR-22.
- AC-6 (FR-6): Each searchable field supports partial matching; filters combine with AND, ignoring case/accents, such that `jose` matches `José`. Results show first name plus optional surnames. No matches display “No se encontraron usuarios”. Reassociating an existing member displays “El usuario ya pertenece al grupo”, without duplicate membership, mutation, redraw, or new assignment email.
- AC-7 (FR-7): An owner can create/edit an event with only a name; absent names fail, optional date/notes can be supplied, and each event has exactly one group. After a valid draw, changing group name/description or event name/date/notes leaves its assignments unchanged and does not trigger redraw.
- AC-8 (FR-8): An owner can list and delete events of owned groups; a USER without ownership cannot.
- AC-9 (FR-9): An owner can finish an event with no draw, an invalid draw, or a valid draw; completion writes the current system date/time into the single completion field, overwriting any future value, and closes the event immediately.
- AC-10 (FR-10): A draw includes every current group member, including the owner, each exactly once as giver and recipient, with no self-assignment. All complete valid assignments are equiprobable. The plan shall demonstrate this through algorithm reasoning and exact small-case checks, with supplementary randomized checks as appropriate; observed variation alone does not prove fairness. Fewer than three members invoke AC-26.
- AC-11 (FR-11): Once a valid draw exists, manual attempts to change or rerun it fail while assignments remain unchanged; the automatic replacement in AC-25 is allowed.
- AC-12 (FR-12): A USER cannot explicitly delete a draw; SUPER ADMIN can for both open and finished events. Deleting a finished-event draw leaves that event closed; attempts to draw it again fail. Open events still follow minimum-member rules.
- AC-13 (FR-13): Assignment email contains event name and recipient first name plus optional surnames. Failed delivery preserves assignments; after all retries fail, owner and SUPER ADMIN see the failure, without assignment disclosure, and can request authorized resend for a current valid unfinished-event assignment. Queued initial sends/retries/resends for superseded assignments or closed events are discarded. Resend permissions remain enforced.
- AC-14 (FR-14): Database inspection cannot read the stored assigned recipient in clear text, and authorized notification processing recovers the correct recipient.
- AC-15 (FR-15): The correct password with either the account's email or phone permits login and leads to the dashboard; incorrect credentials fail. No public account-registration operation is available.
- AC-16 (FR-16): Only own assignments in unfinished events produce cards; valid recipients are initially concealed. Invalid draws show “Participantes insuficientes” without allowing previous-assignment reveal. Requests to view another user's assignment fail for USER and SUPER ADMIN alike. Finished events do not produce these cards.
- AC-17 (FR-17): Reveal displays the correct recipient and conceals it after 20 seconds from the latest activation; activating again during visibility restarts the period.
- AC-18 (FR-18): The dashboard ownership card lists the current user's owned groups.
- AC-19 (FR-19): Users navigation displays the specified list and permits authorized creation, listing, association, and removal; it does not grant owners permission to modify other users' data or delete their accounts. SUPER ADMIN and own-account exceptions follow FR-22/23/29.
- AC-20 (FR-20): Groups navigation displays owned groups and permits member association using both creation and search.
- AC-21 (FR-21): Events navigation displays the specified list and actions, enforcing FR-12 for deletion and FR-9 for completion.
- AC-22 (FR-22): SUPER ADMIN can perform specified management operations on groups and events owned by other users but cannot view another user's assignment.
- AC-23 (FR-23): A USER may delete their own account but cannot delete another account; SUPER ADMIN may delete either. Deleting an owner removes owned groups and dependent events/draws, retaining other members' accounts. Surviving assignment references to the deleted user become null, including historical references in finished events, without redrawing finished events. Both deletion paths remove surviving memberships and invoke AC-25 for affected unfinished events, subject to AC-27.
- AC-24 (FR-24): Removing another member from an owned group removes that membership while the global account and its memberships in other groups remain; a USER who does not own the group cannot perform this group-management action.
- AC-25 (FR-25): Test self-deletion, SUPER ADMIN account deletion, owner-driven removal, and adding a member after a valid draw separately. Affected surviving unfinished-event draws are replaced when at least three members are available, using current membership and emailing each participant the new assignment. Added members participate and removed users are excluded. Finished-event draws never repeat. Insufficient members invoke AC-26; delivery failures follow AC-13/34.
- AC-26 (FR-26): Initial draws and automatic redraws with zero, one, or two available members create no new assignments. When an unfinished-event redraw becomes impossible, previous assignments remain stored and are marked invalid. Available members receive an insufficient-participant email. When membership returns to at least three, an affected unfinished-event draw is automatically replaced and new assignments emailed.
- AC-27 (FR-27): Every membership removal displays its consequences and requires the acting user's confirmation, including account-deletion paths. Without confirmation, removal and its dependent changes do not execute. A special insufficient-participant warning appears when fewer than three would remain, even though confirmation is also required when enough members would remain.
- AC-28 (FR-28): A current emailed recovery link permits setting a valid password before expiry. Issuing a second link invalidates the first; successful use invalidates the used link; expired links fail. Default validity is one hour; configuration changes affect newly issued links. The reset password permits login.
- AC-29 (FR-29): During a session, a user can update their own account data and password under existing validation and uniqueness constraints; unauthenticated requests cannot perform those updates. Changing another member's data is not authorized by group ownership.

Manual closure updates the same field as specified by AC-9.
- AC-32 (FR-32): Concurrent closure prevents new/replacement draws for the closed event, while authorized group member changes succeed without redrawing its finished-event draws. Unfinished events in the same group still follow automatic redraw rules.
- AC-33 (FR-33): Two concurrent draw requests produce one draw, with the second requester receiving an already-performed notice. No duplicate assignments or duplicate initial-draw notification set is created; closure priority remains applicable.
- AC-34 (FR-34): An initial failure permits at most five additional retries, six sends total. For base 30 seconds, successive retry delays after failure are 30/60/120/240/480 seconds. Changing the base scales delays. Success ends that sequence; closure/replacement discards pending deliveries. Exhaustion is visible to owner and SUPER ADMIN under AC-13 and permits authorized manual resend.
- AC-35 (FR-35): After logout, protected operations made through the previous session fail authentication and require login; a subsequent valid login restores access.

## Edge cases and precedence

- Zero, one, or two members: no initial/replacement draw; retain affected previous assignments as invalid, hide reveal, and email current members. With no members, there are no email recipients (FR-16/26). Returning to three replaces affected unfinished-event draws automatically.
- Duplicate association: no membership mutation, redraw, or new assignment notification; display the specified message (FR-6).
- Shared users: owner removal affects membership only; account deletion cascades through owned data but preserves other member accounts, clears surviving user references to null, and updates surviving unfinished-event draws (FR-23/24/25).
- Precedence: finished-event restrictions override automatic redraw and resend; membership changes still proceed. Manual closure updates the shared field immediately; scheduled closure blocks draw activity at the selected day's boundary, independently of background processing (FR-9/12/25/31/32; NFR-9).
- Concurrent draw requests produce one draw and one already-performed notice, without duplicate assignments/initial notification sets (FR-33).
- Notification failure never reruns the draw. Five retries follow the initial send; stale assignment deliveries are discarded on replacement/closure, and exhausted failures remain visible to owner/SUPER ADMIN without exposing assignments (FR-13/34).
- Superseded, used, and expired recovery links fail; logout ends access through the session (FR-28/35).
- Invalid input uses the approved validation rules; loading, empty, and failure UI states remain visible in Spanish with associated form errors (FR-3/6/31; NFR-8).
